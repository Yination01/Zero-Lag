# Building Zero-Lag

The shipping stack is Expo / React Native Android. This repo holds the app
source and the gate. The `android/` folder is generated by prebuild and is
gitignored, never edited by hand.

## Gate

```bash
npm test
```

Runs the two agent audits and the pure-TS app tests (readiness math, RTT
probe). Exit code must be 0.

## Build the APK (cloud, budget free tier)

The APK is cut by EAS cloud build. Do not run this unless a build number
was named in the current turn (CLAUDE.md rule 1).

1. Install once: `npm install` then `npm i -g eas-cli`.
2. Log in to Expo and link the project: `eas login`, `eas init`.
3. Record the build number in the release message and update
   `.build-state.json` at dispatch.
4. Internal test APK:
   `eas build -p android --profile preview --non-interactive`
   Needs `EXPO_TOKEN` in CI or an interactive login locally. With no token
   and no login, the gate fails closed and no build runs.
5. The download URL is the installer testers install on their Android
   phone.

## Build locally (no EAS account)

```bash
npm install
npx expo prebuild --platform android   # generates gitignored android/
npx expo run:android                    # needs Android Studio + JDK 17
```

## What runs on the phone in this build

- Match readiness test: real RTT probes to Cloudflare/Google anycast, then
  ping, jitter, packet loss and a MATCH READY / PLAYABLE / RISKY verdict.
- Guided one-tap network refresh: opens airplane mode settings with steps.
- Signal dBm and the floating ping HUD are compiled from the plugins in
  `plugins/` during prebuild. They are native code and are NOT verified
  until a build runs them on a real device.
