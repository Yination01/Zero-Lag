# Building Zero-Lag

Stack: Expo / React Native Android. The `android/` folder is generated by
prebuild and gitignored, never edited by hand.

## Gate

```bash
npm install
npm test
```

Runs four checks, all must pass:
1. agent docs (`.audit/agent-docs.cjs`)
2. agent hard rules (`.audit/agent-rules.cjs`)
3. legal pack (`.audit/legal.cjs`)
4. app unit tests (`src/**/*.test.ts`)

## Build the APK with EAS (cloud, free tier, no Android Studio needed)

Run these on your own machine. A named build number is required (rule 1).

1. Install and log in:
   ```bash
   npm install -g eas-cli
   eas login          # create a free Expo account if you do not have one
   eas init           # accept the defaults to link the project
   ```
2. Make the build (uses the preview profile, which produces an APK):
   ```bash
   eas build -p android --profile preview
   ```
3. When it finishes EAS prints a download link. Open it on your Android
   phone to install the APK.

## Build the APK locally (offline, needs Android Studio + JDK 17)

```bash
npm install
npx expo prebuild --platform android
cd android && ./gradlew assembleDebug
# APK: android/app/build/outputs/apk/debug/app-debug.apk
```

## GitHub Actions EAS workflow (manual, named-build gated)

A workflow template is staged at `.github/workflow-disabled/apk.yml.txt`
because the agent GitHub token cannot create files under
`.github/workflows` (it lacks the workflows permission). To enable it once:

1. Copy the template into place and push it yourself:
   ```bash
   cp .github/workflow-disabled/apk.yml.txt .github/workflows/apk.yml
   git add .github/workflows/apk.yml
   git commit -m "ci: enable manual EAS APK build workflow"
   git push
   ```
2. Add an `EXPO_TOKEN` secret: create a token at
   https://expo.dev/settings/access-tokens, then add it as a repo secret
   named `EXPO_TOKEN` in GitHub Settings, Secrets and variables, Actions.
   Without the token the workflow fails closed.
3. Dispatch: GitHub repo, Actions tab, "Build Zero-Lag APK", Run workflow,
   type a build number (for example `build-2`), Run. No number, no build.

The workflow only triggers manually, requires a typed build number, and
aborts if `EXPO_TOKEN` is absent.

## What runs on the phone

- First launch: legal consent (Terms, Privacy, EULA), then guest or
  account, then permissions. Guests have full unrestricted access.
- Home: match-readiness test (ping, jitter, loss, verdict).
- Game: foreground game detection (Usage Access) with per-game headline
  (COD estimated ping, eFootball network strength).
- Boost: start the floating game bar (live ping + RAM over games and in
  the notifications shade), and honest guided actions (hogs, Game Mode
  DND, refresh, storage, DNS pending). Each action states what it does and
  why it works.
- Device: recognized model, tier, and battery/balanced/performance levels.

The native pieces (overlay, telephony, device facts, foreground detection)
compile only at prebuild/EAS and are verified on a real device.
