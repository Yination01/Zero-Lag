# Building Zero-Lag

Stack: Expo / React Native Android. The `android/` folder is generated by
prebuild and gitignored. Never edit generated Android files by hand.

## Source gate

```bash
npm ci
npm test
```

The gate runs all of these checks and must pass before a preview APK is
requested:

1. agent docs (`.audit/agent-docs.cjs`)
2. agent hard rules (`.audit/agent-rules.cjs`)
3. legal pack (`.audit/legal.cjs`)
4. TypeScript (`tsc --noEmit`)
5. app unit tests (`src/**/*.test.ts`)

### Known dependency-security follow-up

As of 2026-09-02, `npm audit --omit=dev` reports 31 advisories in the locked
Expo 51 and React Native 0.74 toolchain, including one critical transitive
advisory. The automated remediation requests a major Expo and React Native
migration. Do not run `npm audit fix --force` for this app; schedule that SDK
migration as dedicated compatibility and Android device-validation work.

## Recommended preview APK route: manual GitHub Actions dispatch

The checked-in workflow is `.github/workflows/apk.yml`. It is manual only,
requires a build number, and fails closed if the repository does not hold an
`EXPO_TOKEN` Actions secret.

Use this route only after the maintainer has explicitly named the build and the
source commit is pushed:

1. Open the repository's **Actions** tab.
2. Select **Build Zero-Lag APK** and choose **Run workflow**.
3. Select the pushed branch, normally `main`.
4. Enter the named build value, for example `build-9`, and keep the `preview`
   profile selected.
5. Run the workflow. A green GitHub workflow confirms source gating and EAS
   submission. It does not itself prove that EAS finished Android compilation.
6. Open the EAS build page that the workflow reports. Install an APK only after
   EAS reports **Finished**, then use `docs/DEVICE_TEST_PLAN.md` on a real
   Android phone.

Do not reuse an old build number as evidence for changed source. Record the
new dispatch and terminal EAS state in `.build-state.json`.

## Direct EAS route

Run this only on a maintainer machine after the build has been named:

```bash
npm install -g eas-cli
eas login
eas build --platform android --profile preview
```

EAS prints a build page and, after success, an APK installation link. Keep
credentials out of source files, logs, commits, and screenshots.

## Local Android route

A local build needs JDK 17 and a working Android SDK or Android Studio. The
maintainer must specifically authorize generated Android work before running
prebuild:

```bash
npm ci
npx expo prebuild --platform android
cd android && ./gradlew assembleDebug
# APK: android/app/build/outputs/apk/debug/app-debug.apk
```

## What runs on the phone

- First launch: legal consent, a truthful local guest start screen, then Android
  runtime permissions. No email, password, login, account, or cloud backup is
  offered.
- Home: a public-edge match-readiness estimate and compact on-device results.
- Game: foreground-game detection after the person grants Android Usage Access,
  with a per-game headline. It does not fabricate a game when none is detected.
- Boost: an Android floating HUD and guided settings actions. The HUD estimate
  is not exact in-game ping, and a foreground notification offers Stop HUD.
- History: full, bounded, on-device readiness history with irreversible local
  deletion.
- Device: recognized model, tier, and battery, balanced, or performance
  profiles. Profiles alter Zero-Lag's sampling and HUD interval, not device
  clock speeds or game settings.

Native pieces such as overlay service, telephony facts, foreground-game
detection, notification behavior, and Android permission behavior are only
verified after a successful Android build and real-device check.
